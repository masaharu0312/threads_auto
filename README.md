# Threads 自動投稿（どこでもMUSEE 採用・オーナー募集）

1日3投稿（朝：働きたい人／昼：オーナー候補／夜：共感・ブランド）を、画像付きで自動投稿します。

## 毎週の流れ
1. **日曜 10:00**：Claude が翌週7日分（21投稿）の本文と画像を作り、スプレッドシート「投稿」に追加します。
2. **あなた**：本文と画像（プレビュー列）を確認し、「承認」にチェックします。文言は直接直してOKです。
   - 画像の文言（画像見出し・画像本文・画像注記）を直した場合も、投稿時に画像が作り直されます。
   - 本部提供の写真を使いたいときは `assets/photos/` に置き、「写真ファイル」列にファイル名を書きます。
3. **毎日 8:00 / 12:30 / 20:30**：承認済みの投稿だけが自動で投稿されます。未承認の投稿は見送られます。
4. 結果（状態・投稿URL・エラー）はシートに書き戻されます。失敗すると GitHub から通知メールが届きます。

※ GitHub Actions の定時実行は、混雑時に数分〜30分ほど遅れることがあります。

## 月額費用の目安
| 項目 | 目安 |
|---|---|
| Claude API（週7回の生成） | 月 数百円程度 |
| GitHub Actions（公開リポジトリ） | 無料 |
| Google Sheets・Threads API | 無料 |

## 初期設定（最初に1回）

### 1. GitHub リポジトリを作る
- このフォルダを **公開（Public）リポジトリ** として push します。
  - 画像を Threads に読み込ませるために、画像を公開URLに置く必要があるためです。
  - 公開されるのはコードと投稿画像だけです。トークンやキーは Secrets に入れるので公開されません。

### 2. Google スプレッドシートとサービスアカウント
1. 空のスプレッドシートを作り、URLの `/d/` と `/edit` の間の文字列（シートID）を控えます。
2. Google Cloud で Sheets API を有効にし、サービスアカウントを作って JSON キーをダウンロードします。
3. スプレッドシートを、サービスアカウントのメールアドレスに「編集者」で共有します。

### 3. Anthropic API キー
- https://console.anthropic.com で API キーを発行します。月の上限額（例：1,000円相当）も設定しておくと安心です。

### 4. Threads のアクセストークン
1. https://developers.facebook.com でアプリを作り、ユースケースで「Threads API にアクセス」を選びます。
2. 権限 `threads_basic` と `threads_content_publish` を追加します。
3. 「役割」で自分の Threads アカウントをテスターに追加し、Threads アプリ側で招待を承認します。
4. 「ユーザートークン生成ツール」でトークンを発行します。

### 5. GitHub Secrets に登録（Settings → Secrets and variables → Actions）
| 名前 | 中身 |
|---|---|
| `SHEET_ID` | スプレッドシートID |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | サービスアカウントの JSON キーの中身すべて |
| `ANTHROPIC_API_KEY` | Anthropic の API キー |
| `THREADS_TOKEN` | Threads のトークン |
| `THREADS_APP_SECRET` | Meta アプリの「app secret」（短期トークンを長期に交換するため） |

### 6. 初期設定を実行
- Actions タブ →「初期設定（シート作成・トークン登録）」→ Run workflow。
- スプレッドシートに「投稿」「設定」シートができます。

### 7. 「設定」シートを埋める
- 表示名、オーナー向け誘導先、求人の誘導先、求人条件 などを入力します。
- 「必須表記」は毎回の本文末尾に自動で付きます。紹介報酬を受け取る立場なら、広告であることの表示（#PR など）は残してください。

### 8. 試しに動かす
- Actions →「翌週の下書きを作成」→ Run workflow（開始日に今日、日数に1）。
- シートで1件承認し、Actions →「Threads 投稿」→ 枠を選んで Run workflow。

## 語り口について
- 投稿は「加盟店オーナー本人が、個人的な所感を交えて語る」形で作ります。ルールは `knowledge.md` の「発信の立場と語り口」にあります。
- `voice_examples.json` は、オーナー本人が「実感と合っている」と確認した投稿です。AIはこれを語り口の見本にします。気に入った投稿が増えたら差し替えてください。
- 手で用意した下書き（例：`drafts/2026-10-26_week_v2.json`）をそのままシートに入れるときは、Actions →「翌週の下書きを作成」の `from_json` にファイルのパスを入れて実行します。

## 運用のメモ
- Threads のトークンは60日で切れます。毎週の下書き作成時に自動で延長します。
- 投稿内容のルール（収益を約束しない、効果を断定しない など）は `knowledge.md` にあります。資料が更新されたらここを直してください。
- 画像デザインの確認：`python3 src/preview.py` で `preview/` に見本画像ができます。
